# P16 — 主题人格与趣味文案系统

更新日期：2026-09-09

## 目标

让主题不再只是“换角色名和头像”，而是贯穿 `Agent 群聊` 的默认体验：空态、草案、确认、取消、阶段推进、执行状态、错误提示都要更人话、更有趣，同时不影响交付效率。

## 设计原则

- **人话优先**：用户不需要理解 agent、workflow、orchestration 等术语，也能知道下一步该点什么。
- **轻度人格**：允许沙雕、三国、原神等口吻，但不能为了角色扮演水字数。
- **任务推进**：每条文案都应该让用户知道当前状态、下一步动作或风险。
- **主题可插拔**：主题文案集中在 `theme-voice.ts`，后续新增主题不散落到各处组件。
- **默认沙雕但靠谱**：默认主题继续使用 `meme_comedy`，表达轻松，但确认、写入、执行状态必须明确。

## 文案覆盖范围

| 场景 | 示例 |
|---|---|
| 空态 | “把任务扔进群里，AI 小队就能开整。” |
| 信息不足追问 | “这活儿还缺一句背景，不然小队容易原地整活。” |
| 草案生成 | “先别急着开工，我先把小队名单和作战流程摆出来。” |
| 确认写入 | “已写入当前工作区，小队挂牌营业。” |
| 取消草案 | “草案已撕票，当前配置没动。” |
| 状态待命 | “小队待命中，还没人被点名干活。” |
| 执行中 | “执行中 / 已收工 / 翻车了” |

## 当前实现

- `src/engine/theme-voice.ts`：新增 `ThemeVoiceProfile` 与主题文案目录。
- `src/engine/auto-setup.ts`：草案、确认、取消、追问文案接入主题 voice。
- `src/index.ts`：取消草案和信息不足追问改用统一 voice 文案。
- `src/client/GroupChatPanel.tsx`：中间空态、Agent 状态、快捷按钮文案改成人话表达。
- `src/types.ts`：补充 `ThemeVoiceProfile` 类型，便于长期维护。

## 验收标准

- 默认沙雕主题能输出轻松但明确的草案/确认/取消文案；
- `formatAutoSetupDraft()` 保留稳定标识 `待确认草案：角色 + 工作流`，兼容现有测试和 UI 判断；
- 文案模块集中，不在多个业务文件中散落硬编码；
- `npm run test:matrix` 通过；
- 浏览器中 `Agent 群聊` 可见，空态和草案确认按钮可见。
