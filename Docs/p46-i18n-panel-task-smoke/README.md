# P46 — 群聊面板投递中英文业务功能开发任务实测

## 测试任务

在 `Agent 群聊` 面板中投递一条真实开发任务：

> 请把这个扩展的中/英文语言业务功能作为一个开发任务来处理：需要识别当前界面语言，所有业务文案、角色主题文案、调度模式 QA、自动创建角色/工作流草案、确认/取消提示、账本和团队面板都支持 zh-CN / en-US；先根据当前项目情况生成角色与工作流草案，用户确认后再写入。

## 结果

- 群聊面板可正常打开。
- 右侧 HUD 可正常显示。
- 消息投递后自动生成“待确认草案：角色 + 工作流”。
- 草案包含 `zh-CN / en-US` 业务目标。
- 没有出现 `prepare`、`resume failed`、`unscoped context` 等历史错误。
- HUD / 中间消息没有横向溢出。

## 暴露并修复的问题

### 问题：角色名从任务开头硬截取

首次实测时，自动建队把任务开头“请把这个扩展…”硬截为角色名前缀，生成了：

- 请把这个总控官
- 请把这个情报官
- 请把这个底座官

这类名字不符合“人话、有趣、贴合业务”的目标。

### 修复

在 `src/engine/theme-factory.ts` 新增 `deriveThemePrefix()`：

- 过滤“请把 / 帮我 / 这个 / 扩展 / 插件 / 功能 / 业务 / 生成 / 工作流 / 草案”等泛化指令词；
- 对中英文、双语、i18n、zh-CN、en-US 类任务优先生成 `双语` 前缀；
- 对 UI、调研、文档等任务生成更贴近业务的前缀。

修复后同一任务生成：

- 双语总控官
- 双语情报官
- 双语底座官
- 双语门面官
- 双语挑刺官
- 双语人话官

## 结论

当前群聊面板能把“中/英文语言业务功能”识别为一个需要用户确认的开发草案，确认前不会写入工作区。实测也证明了一个产品问题：自动生成角色名不能简单截取任务开头，必须先剔除指令噪声并识别业务关键词。

浏览器回归字段：hasFixedNames=true、hasBadRoleNames=false、overflow=0、rrors=[]。
