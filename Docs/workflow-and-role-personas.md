# DSH 多 Agent 群聊：角色、主题与工作流规约

更新日期：2026-09-10

## 1. 默认角色体系

| 角色 ID | 用户可见角色 | 职责 |
|---|---|---|
| `commander` | 主 Agent / 总控 | 理解、追问、拆解、分派、审核、收口 |
| `researcher` | 调研专员 | 搜索、爬取、资料整理 |
| `backend` | 后端专员 | 状态、API、持久化、工程实现 |
| `frontend` | 前端专员 | UI、交互、浏览器验证、视觉修复 |
| `qa` | 质检红队 | 测试、边界、风险、验收 |
| `writer` | 文档写手 | 文档、总结、发布说明 |

## 2. 主题体系

内置主题：

- 默认（沙雕整活）
- 沙雕整活
- 原神提瓦特
- 现代精英
- 三国风云
- 科技传奇：乔布斯 / 马斯克 / 黄仁勋 / 雷布斯 / 比尔·盖茨 / 张小龙

### 科技传奇职责映射

| 角色 ID | 科技传奇人物 | 主题职责感 |
|---|---|---|
| `commander` | 史蒂夫·乔布斯 | 产品暴君、最终拍板、发布会级验收 |
| `researcher` | 埃隆·马斯克 | 第一性原理、调研拆解、机会发射 |
| `backend` | 黄仁勋 | 算力底座、架构稳定、性能榨干 |
| `frontend` | 雷布斯 | 极致性价比、发布会门面、真香体验 |
| `qa` | 比尔·盖茨 | 系统兼容、边界挑刺、发布前扫坑 |
| `writer` | 张小龙 | 少即是多、人话体验、少想一步 |

默认自动创建使用“沙雕整活”主题，但角色必须：

- 说人话。
- 有轻微趣味性。
- 服务任务推进。
- 不水字数，不把角色扮演置于交付之上。

## 3. 自动生成角色与工作流

用户可以在中间 `Agent 群聊` 输入主题/任务简述，系统根据世界观和项目任务生成：

- 角色名册
- 主 Agent + SubAgent 策略
- 模型建议
- 工具路由
- 工作流阶段
- 质量门禁

生成结果必须先作为草案展示，用户确认后才写入工作区。

## 4. 工作流默认模板

默认面向项目协作的 5 阶段：

1. 需求澄清与目标对齐。
2. 拆解任务、确认依赖和角色分工。
3. 前后端/文档等并行原型实现。
4. QA 红队、边界测试与质量验收。
5. 文档沉淀、主 Agent 结题收口。

阶段名称可以随主题人话化，例如“先把话说人话”“拆活别拆家”“原型开整”“边界爆破与体验验收”“收口交付别烂尾”。

## 5. 模型推荐

模型配置不写死，按能力标签推荐：

- reasoning：总控、复杂决策
- coding：后端/前端实现
- tool_use：工具调用与执行链
- web_research / data_extraction：调研与资料抽取
- ui_design：UI 美化与交互
- writing：文档与表达
- qa_audit：审计与测试
- fast_reply / low_cost：轻量响应

用户手动配置优先，最近模型记录最多 6 条，回退模型按顺序尝试。
