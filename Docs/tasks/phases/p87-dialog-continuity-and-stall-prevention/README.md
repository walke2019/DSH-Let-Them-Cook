# P84 对话连贯性与防终止防死锁治理 (Dialog Continuity & Anti-Stall Engine)

## 一、背景与问题根因
在复杂的单智能体或多智能体交互中，用户常遇到“短对话突然终止”、“长对话流程中途卡死”、“智能体不继续干活”的情况。
经过对调度器（`DispatchArbiter`）、运行时（`agent-runtime`）、看门狗超时机制与工作流状态机的全链路排查，锁定了以下六大核心根因：

1. **工作流未审核阶段死锁**：当阶段配置为非审批阶段（如 `stage_implementation` 的 `requiresApproval: false`）或非当前阶段成员发言时，原调度器直接返回 `isTerminal: true`，导致 SubAgent 产出后无任何后续调度，会话永久冻结。
2. **指挥官推进关键词狭隘**：原逻辑仅匹配中文字符串 `通过` / `批准` / `下一阶段`；若指挥官使用英文（如 `Approved`, `Proceed`, `Pass`）或中式常用语（如 `准予推进`, `验收合格`），状态机不推进，造成多智能体流程断档。
3. **单次协作轮次硬熔断过低**：原 `maxTurnsPerPrompt` 硬编码为 6 轮。标准五阶段工作流（包含调研、初审、实现、QA、文档、终审）至少需要 6~10 轮交互，第 7 轮直接被 `circuit_breaker` 硬熔断斩断。
4. **模型异常或看门狗超时静默截断**：当 SubAgent 遭遇网络波动、模型 429、或耗时较长被看门狗终止时，原逻辑仅在本地报错并直接 `return`，未通知指挥官介入收拢，导致群聊陷入死寂。
5. **看门狗超时预算对于长任务过紧**：原后端与前端任务限额仅 120s，在复杂代码建模和多步工具调用下容易误触看门狗 124 退出。

## 二、架构治理与修复方案

### 1. 全生命周期回传主控 (Universal Master Handoff)
- 任何 SubAgent（非 commander）在产出完成或报告后，若未显式 @ 其他专家，一律无条件回传给 `[commander]`。
- 彻底消除了“阶段不需要审批就无人接管”的逻辑黑洞。

### 2. 多语言与容错工作流推进识别 (Multi-keyword & Bilingual Advance)
- 支持 `通过`、`批准`、`下一阶段`、`准予`、`合格`、`推进`、`approve`、`approved`、`proceed`、`next stage`、`pass`、`lgtm`。
- 指挥官在批准时若指定了具体责任人（如 `@黄仁勋 @雷布斯`），优先按指挥官指定成员唤醒；若未指定则自动唤醒下一阶段责任人。

### 3. 动态自适应轮次熔断 (Dynamic Interaction Budget)
- 针对短任务（`quick`）：维持紧凑的 6~8 轮上限，防止单问单答场景发散。
- 针对长任务（`long` / `workflow_driven`）：自动提升至 **24 轮** 充足配额，保障通用五阶段闭环顺畅跑通。

### 4. 故障自动介入兜底 (Failure Auto-Recovery)
- 任何 SubAgent 遭遇执行异常或看门狗超时，系统自动向主 Agent 的 Mailbox 发送异常告警信息，并在 1.5 秒后自动唤醒指挥官介入接管。
- 指挥官可以重新评估方案、指定降级模型或向人类负责人汇报，彻底杜绝无响应停摆。

### 5. 看门狗超时预算自适应放宽
- 长任务执行预算放宽至 180s ~ 360s，充分保障深度思考与编码。
