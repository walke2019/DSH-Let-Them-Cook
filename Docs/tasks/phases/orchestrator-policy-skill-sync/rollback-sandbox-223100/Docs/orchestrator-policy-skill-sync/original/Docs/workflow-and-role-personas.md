# DSH 多 Agent 群聊：角色体系、流程化工作流引擎与主题昵称映射规约

---

## 1. 业务愿景与通用化扩展定位

通过将多智能体协同解耦为**角色能力边界（Capabilities）**、**权限控制策略（Access Control List）**与**流程化工作流定义（Workflow Orchestration）**，系统不再局限于软件研发场景，而是能够通用于任何复杂的跨行业团队协同任务（如投研分析、影视创作、法务咨询、医疗多学科会诊、电商营销等）。

---

## 2. 六大核心职责角色定义与外呼能力矩阵

| 核心角色代码 | 职责定义与专业边界 | 权限级别 | 允许调用工具能力（Capability Matrix） |
| :--- | :--- | :--- | :--- |
| **`commander`** (总指挥官) | 全盘目标拆解、各环节成果审核门控（Approval Gate）、派发指令、仲裁收官 | **Admin** (全读写、审核特权) | `group_chat_set_mode`, `workflow_*`, `group_chat_export_summary` |
| **`researcher`** (搜索调研) | 外部信息搜索检索、目标网页抓取解析、竞品/材料调研、精炼总结 | **Read/Write** (限定外呼) | `web_search`, `stealth_navigate`, `stealth_read_page`, `summarize` |
| **`backend`** (后端/逻辑层) | 数据流建模、核心算法与业务逻辑实现、接口数据契约、性能与并发控制 | **Read/Write** (受限代码区) | `tool_fs`, `code_runtime` (受限目录) |
| **`frontend`** (前端/UI表现层)| 用户交互原型设计、界面视觉美化、响应式排版、无障碍与动效体验 | **Read/Write** (受限UI区) | `tool_fs` (受限组件目录), `modlens_read_image` |
| **`qa`** (测试/红队专家) | 边界用例推演、安全漏洞审计、异常场景红队对抗、逻辑漏洞挖掘 | **Audit-Only** (只读审计) | 严禁写操作，仅可发表审查报告与红队质疑 |
| **`writer`** (文档/成果写手) | 整理阶段性会议纪要、生成正式交付物（PRD/方案白皮书/用户手册）、黑板维护 | **Documentation** (文档写) | `group_chat_update_scratchpad`, `write_deliverable` |

## 3. 工作流（Workflow Pipeline）执行与上报闭环机制

### 3.1 闭环流转全景（各角色完成任务后必须向总指挥官汇报）
在工作流执行过程中，系统确立了**“专员执行 ➔ 汇报总指挥 ➔ 指挥官审核把关 ➔ 批准流转下一阶段”**的确定性闭环：

```
                    ┌────────────────────────────┐
                    │ 阶段一：搜索调研 (Researcher) │
                    └─────────────┬──────────────┘
                                  │ 完成调研并向指挥官汇报
                                  ▼
                    ┌────────────────────────────┐
                    │ 阶段二：指挥官审核把关与分工  │ ◄── [门控 Approval Gate]
                    │    (Commander Review)      │     (可驳回重整 / 批准放行)
                    └─────────────┬──────────────┘
                                  │ 批准并派发实现任务
                                  ▼
         ┌────────────────────────┴────────────────────────┐
         ▼                                                 ▼
┌───────────────────┐                             ┌───────────────────┐
│ 阶段三(A)：后端架构│                             │ 阶段三(B)：前端UI  │
│     (Backend)     │                             │    (Frontend)     │
└────────┬──────────┘                             └─────────┬─────────┘
         │                                                  │
         └────────────────────────┬─────────────────────────┘
                                  │ 并行实现完毕，向总指挥官汇报
                                  ▼
                    ┌────────────────────────────┐
                    │ 阶段四：红队测试与审计 (QA)  │
                    └─────────────┬──────────────┘
                                  │ 输出审计报告并向总指挥官汇报
                                  ▼
                    ┌────────────────────────────┐
                    │ 阶段五：文档沉淀与终审验收   │
                    │   (Writer & Commander)     │ ◄── [最终验收结题签字]
                    └────────────────────────────┘
```

### 3.2 界面架构与 dsh-better-sidebar 工业级 Layout-Push 融合
系统参考了官方生态顶级右栏扩展 **`dsh-better-sidebar`** 的架构设计，实现了真物理分栏融合：
1. **真实推挤布局（Layout-Push）**：
   - 绝非简单的绝对悬浮遮罩（Cover Overlay），而是通过动态更新 CSS 变量 `--dsh-group-chat-width`；
   - 自动在 DSH 的 `#root [data-dsh-frame]` 注入 `padding-right`，真实推挤 DSH 中间主对话视窗与底部 Composer 打字框；
   - 展开侧栏时，DSH 原生右侧边界、聊天流滚动条、Details 详情栏手柄自适应向左平移，**100% 保留原生操作视口，无任何像素重叠与遮挡**；
2. **任务过程 Step-Rows 紧凑化**：
   - 抛弃微信式大圆角气泡，将各 Agent 任务过程沉淀为 Codex / Cursor 风格单行步骤折叠条（高仅 26px）；
   - 一屏纵览 15~20 个 Agent 协作节点，点击就地展开 Markdown 成果与思考链。
