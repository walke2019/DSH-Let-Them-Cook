# DSH 多 Agent 群聊插件业务规约

更新日期：2026-09-10

## 1. 产品定位

`dsh-group-chat` 不是简单群聊皮肤，而是 **对话优先、工作区级、可确认写入的多 Agent 项目协同入口**。

用户不需要先理解复杂配置，只需在中间 `Agent 群聊` 标签描述项目任务；扩展负责理解意图、必要追问、生成角色/工作流/模型建议草案，并在用户确认后写入当前工作区配置。

## 2. 主副屏职责

### 2.1 中间 `Agent 群聊` 标签

- 通过 `conversation.view` 新增独立标签，不覆盖官方 `对话`。
- 承接扩展对话、@角色、自动建群草案、确认/取消/补充修改。
- 使用 `GroupChatPanel mode="dock"`，避免历史 full 模式 body 接管。
- 当右侧 HUD 停靠展开时，仅本标签自身避让 HUD；官方对话不受影响。

### 2.2 右侧 `群聊控制台 (HUD)`

- 通过 `shell.overlay` 挂载，定位为后台导播台。
- 展示工作流、执行导演台、共享黑板、成员账本、模型/角色配置。
- 不重复聊天输入，不承担主对话派发。
- 可停靠、可浮动、可拖动位置、可通过左边线缩放宽度。

## 3. 用户确认写入机制

自动创建角色/工作流时必须遵循：

1. 用户输入一句任务说明。
2. 系统判断信息是否足够；不足则追问。
3. 信息足够时生成待确认草案。
4. 用户点击“确认创建”或明确回复确认语义后，才写入 `.pm-workflow/dsh-group-chat/`。
5. 用户可取消或补充修改草案。

任何主题、角色、工作流、模型、回退模型、黑板与任务状态默认都必须是工作区作用域，不得无提示写成全局配置。

## 4. 角色与趣味性原则

- 默认创建主题为“沙雕整活”，但必须服务任务推进。
- 文案优先使用人话：群聊、开整、草案、谁在干活、确认、取消、翻车待捞。
- 角色输出要匹配世界观、人格与职责，但不能水字数、不能过度角色扮演。
- 内置“科技传奇”主题要体现乔布斯、马斯克、黄仁勋、雷布斯、比尔·盖茨、张小龙等科技巨头为用户打工的趣味感。

## 5. UI 体验红线

- 中间视图保持官方清爽风格，只对扩展能力做轻增强。
- 右栏不能遮挡中间输入区；HUD 停靠时 `Agent 群聊` 自身自适应避让。
- 左右留白必须对称；HUD 与中间内容保留约 7-8px 安全缝。
- HUD 文本不得溢出组件；details、summary、按钮、模型 ID、任务标题必须收敛在右栏内。
- 右栏拖动体验对齐官方左栏：透明热区、`col-resize`、Pointer Capture 稳定拖动。
## 6. 双语与开源化原则

- 运行态面向用户的内容自动匹配 zh-CN/en-US：UI、HUD、API、工具输出、Agent Prompt、主题角色与工作流生成内容都需要保持双语路径。
- 源码层面为了方便开源协作，`src/**/*.ts(x)` 注释与内部工程说明优先英文。
- 不得为了“代码英文”删掉中文产品能力；中文角色名、中文 @ 别名、中文 UI 文案属于运行态本地化能力。
