# P49 — 群聊 Agent 超时误判修正

## 判断修正

用户反馈：同一批 free 模型在官方源版对话中可以正常调用。因此本问题不能简单归因于“模型不可用”。

更准确的原因是：群聊插件创建的是独立 Agent turn，并额外叠加了角色系统提示词、工具白名单收口、工作流/黑板/历史上下文和 `whenIdle()` 等待；原先 30 秒超时阈值对这个链路偏激进，容易出现“官方对话能用，群聊 Agent 被提前判超时”。

## 本轮修正

- `ModelResilienceManager` 增加按角色 `latencyPreference` 的有效超时下限：
  - fast：至少 45 秒；
  - normal：至少 90 秒；
  - patient：至少 120 秒。
- 保留用户在角色设置里配置的更大超时时间；若用户配置低于角色下限，则以角色下限为准。
- 失败信息增加总耗时与尝试次数，方便区分：
  - 模型真实不可用；
  - 插件提前超时；
  - 回退链全部失败；
  - 工具/上下文导致的非模型错误。
- 成功调用时写入日志：角色、实际 provider/model、总耗时、尝试次数。

## 后续验证方式

1. 用官方对话确认目标模型能正常回答；
2. 在 Agent 群聊里用同一模型触发一个短任务；
3. 看 HUD 闭环质量是否从 `未完成` 转为 `待收口/闭环通过`；
4. 若仍失败，根据错误中的 `总耗时` 和 `尝试次数` 判断是否需要继续调大角色超时或精简上下文。
